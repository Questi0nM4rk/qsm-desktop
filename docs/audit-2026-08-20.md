## Majors found, root causes CONFIRMED in code, fixes planned but NOT applied

1. **UX-2 — panel intent zone steals any open modal.** `EdgeScene.qml` `panelIntentTimer`
   (interval 150) guards only `ShellState.modal !== "panel"`, so hovering the top-center
   handle zone silently replaces the cheat sheet (measured: modal cheatsheet → panel while
   mousing toward the sheet's own search field). Fix: trigger only when
   `ShellState.modal === "none"`.
2. **UX-1 — any pointer event while a modal is open re-fires `open()`** (query wiped, mode
   reset, 4/4 repro with synthetic events) and once left the modal with DEAD keyboard focus
   (Escape stopped closing; IPC needed). Hypothesis (not yet code-traced): the
   `ShellState.focusedScreen` computed binding (ShellState.qml:32) re-evaluates on Hyprland
   focusedMonitor notify and momentarily returns the `screens[0]` fallback (HDMI!) →
   `launcherActive` flickers → `onLauncherActiveChanged` re-runs `open()` → `setText("")`,
   and `WlrLayershell.keyboardFocus` flaps Exclusive→None→Exclusive. Fix direction: make
   focusedScreen sticky (only reassign when a real monitor lookup succeeds), and/or make
   surface `open()` idempotent against re-fire. NEEDS a live trial with the real mouse
   first (below) to grade blocker vs automation-only.
